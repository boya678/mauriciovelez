PRINCIPIOS DEL DISEÑO
====================================================================
1. conversations.phone almacena SIEMPRE el identificador de envío:
   - número real  (ej. "573001234567")   → campo "to" en la API de Meta
   - BSUID        (ej. "CO.194926695…")  → campo "recipient" en la API
   El helper _to_field() en whatsapp.py distingue por la presencia de "."

2. Se NUNCA actualiza conv.phone con el número real obtenido de pedir_contacto.
   El BSUID es el identificador permanente para enviar. El teléfono real
   es solo metadata de negocio guardada en la tabla contactos.

3. contactos.id = teléfono real (clave de negocio)
   contactos.bsuid = BSUID vinculado (índice único)
   Buscar "¿ya tenemos el teléfono de este BSUID?" = SELECT id FROM contactos WHERE bsuid=?

4. pedir_contacto se envía automáticamente al inicio de cada conversación
   nueva con BSUID, MIENTRAS el BSUID no tenga entrada en contactos.
   Una vez el usuario comparte su número → entra en contactos → nunca más se pide.

LÓGICA DE WEBHOOK (entrada)
====================================================================
Archivo : chatsystem/backend/app/api/webhook.py
Cambios:
  - Extrae bsuid = from_user_id del mensaje
  - stable_id = bsuid OR phone  →  conversation_id = uuid5(tenant.id:stable_id)
    Esto hace que el hilo sea estable aunque el teléfono sea desconocido.
  - Payload del stream incluye campos: bsuid, real_phone (en webhook contacts)

Archivo : chatsystem/backend/app/services/whatsapp.py
Cambios en parse_incoming_message:
  - Extrae phone_from (campo "from") y bsuid (campo "from_user_id") por separado
  - sender_id = phone_from OR bsuid
  - Maneja message_type "contacts": extrae real_phone de contacts[0].phones[0]
    y lo pone en campo "real_phone" del dict retornado; content = "[contacto_compartido:PHONE]"
  - Retorna bsuid en el dict de cada mensaje
Nueva función:
  send_request_contact_info(phone_id, token, to, body_text) → POST /messages
    type: interactive / interactive.type: request_contact_info
    _to_field(to) maneja BSUID automáticamente

====================================================================
LÓGICA DE INGESTION (message_ingestion.py)
====================================================================
Archivo : chatsystem/backend/app/workers/message_ingestion.py

CONVERSACIÓN NUEVA con BSUID:
  1. Crea conv con phone=BSUID, bsuid=BSUID
  2. Consulta: SELECT id FROM {schema}.contactos WHERE bsuid = :bsuid
     - Si NO existe → llama send_request_contact_info() automáticamente
       usando tenant.pedir_contacto_message si está configurado, sino texto por defecto
     - Si existe → no hace nada (ya tenemos su teléfono)

CONVERSACIÓN NUEVA con teléfono real:
  - Inserta en contactos (id=phone, username=username) ON CONFLICT DO UPDATE username

MENSAJE EN CONVERSACIÓN EXISTENTE:
  - Actualiza username si cambió
  - Actualiza bsuid si no estaba guardado
  - Si message_type == "contacts" (respuesta al pedir_contacto):
      INSERT INTO contactos (id=real_phone, bsuid=bsuid, username=username)
      ON CONFLICT (id) DO UPDATE SET bsuid, username
      → NO modifica conv.phone
